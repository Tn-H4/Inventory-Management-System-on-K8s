# API Documentation — Inventory Management System

**Production Base URL:** `https://inventory-management-production-6424.up.railway.app/api`

**Local Base URL:** `http://localhost:5050/api`

**Authentication:** All protected endpoints require a JWT token in the `Authorization` header:

```
Authorization: Bearer <token>
```

## API Versioning

**Current version:** v1 (implicit — no version segment in the URL path)

All endpoints currently use the `/api/` prefix without an explicit version segment (e.g., `/api/products`). This is v1 of the API. The versioning strategy below defines how a future breaking change would be introduced.

### Strategy: URL Path Versioning

When a breaking change is needed, a version segment is added to the path:

```
/api/v1/products   ← future explicit v1
/api/v2/products   ← hypothetical breaking v2
```

Both versions would coexist during a deprecation window. Clients on v1 are given a migration period before v1 is retired.

### Why URL Path Versioning

| Approach | Decision |
|---|---|
| URL path (`/v1/`) | **Chosen** — visible, browser-testable, cache-friendly |
| Request header (`Accept-Version: v1`) | Rejected — not testable without tooling |
| Query param (`?version=1`) | Rejected — pollutes query strings, not widely adopted |
| Media type (`Accept: application/vnd.app.v1+json`) | Rejected — complex, rarely practical |

### Migration Plan (when needed)

1. Add `v1` to all controller `@RequestMapping` annotations (e.g., `/api/v1/products`)
2. Update `REACT_APP_API_BASE_URL` in `frontend/.env` to `.../api/v1`
3. Update the Swagger server URL in `OpenApiConfig.java`
4. Verify CORS configuration covers the new path
5. Pilot with one controller, then apply to all 9

**Estimated effort:** ~30 minutes. Zero logic changes required.

### Note on Current State

The omission of `/v1/` from current URLs is intentional for this release. The API is internal (consumed only by this frontend) and has had no breaking changes. Explicit versioning will be introduced the first time a breaking change is needed.

## Auth

### POST /api/auth/login

Login and receive a JWT token.

```json
{ "email": "admin@gmail.com", "password": "123456" }
```

**Response:**

```json
{ "status": 200, "token": "...", "expirationTime": "6 months", "role": "ADMIN" }
```

> **Note:** There is no public self-registration endpoint. All accounts are created by an administrator via `POST /api/users/create`.

## Products

### GET /api/products/all

Returns paginated products. Supports filtering by query params.
| Param | Type | Description |
|-------|------|-------------|
| `categoryId` | Long | Filter by category |
| `warehouseId` | Long | Filter by warehouse |
| `minPrice` | BigDecimal | Price >= minPrice |
| `maxPrice` | BigDecimal | Price <= maxPrice |
| `stockStatus` | String | `IN_STOCK`, `LOW_STOCK`, or `OUT_OF_STOCK` |
| `page` | int | Page number (0-indexed, optional) |
| `limit` | int | Page size (optional) |

**Note:** When `page` and `limit` are provided, returns paginated response with `totalElements` and `totalPages`. Without pagination params, returns a flat list.

### GET /api/products/{id}

Get a single product by ID.

### GET /api/products/search?input={text}

Search products by name or description.

### POST /api/products/add _(ADMIN/MANAGER)_

Add a new product (multipart/form-data).
Params: `imageFile`, `name`, `price`, `stockQuantity`, `reorderThreshold`, `categoryId`, `warehouseId` (optional), `description`

The product code (`sku`) is generated by the backend after insert using `SKU` plus the zero-padded product ID, for example `SKU000123`.

### PUT /api/products/update _(ADMIN/MANAGER)_

Update a product (multipart/form-data).
Params: `productId`, `imageFile` (optional), `name`, `price`, `stockQuantity`, `reorderThreshold`, `categoryId`, `warehouseId` (optional), `description`

Product codes are immutable and are not accepted as update input.

### DELETE /api/products/delete/{id} _(ADMIN/MANAGER)_

Soft-deletes a product (sets `is_deleted = TRUE`).

## Transactions

### GET /api/transactions/all

Returns paginated transactions.
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `page` | int | 0 | Page number (0-indexed) |
| `size` | int | 1000 | Page size |
| `filter` | String | — | Text search across description, product name, type, and status |

**Response:**

```json
{
  "status": 200,
  "message": "success",
  "transactions": [...],
  "totalElements": 120,
  "totalPages": 12
}
```

### GET /api/transactions/{id}

Get a single transaction by ID.

### GET /api/transactions/by-month-year?month={m}&year={y}

Get all transactions for a given month and year.

### GET /api/transactions/export?filter={type}

Export transactions as CSV (max 10,000 rows). Returns `text/csv` with `Content-Disposition: attachment`.

- CSV fields: `Date`, `Type`, `Status`, `Total Products`, `Total Price`, `Product Name`, `Description`
- Field values containing commas, quotes, or newlines are RFC-4180 quoted/escaped

### POST /api/transactions/sell _(all authenticated users)_

```json
{ "productId": 1, "quantity": 5, "description": "..." }
```

### POST /api/transactions/purchase _(ADMIN/MANAGER only)_

```json
{ "productId": 1, "supplierId": 1, "quantity": 100, "description": "..." }
```

### POST /api/transactions/return _(ADMIN/MANAGER only)_

```json
{ "productId": 1, "supplierId": 1, "quantity": 5, "description": "..." }
```

### PUT /api/transactions/{transactionId}

Update transaction status. The request body is a **raw JSON string** (not a JSON object):

```
"COMPLETED"
```

Status values: `"PENDING"`, `"PROCESSING"`, `"COMPLETED"`, `"CANCELLED"`

Example:
```bash
curl -X PUT .../api/transactions/1 \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '"COMPLETED"'
```

## Proposals

Proposal endpoints are for STAFF-submitted inventory actions that require MANAGER/ADMIN approval.

### GET /api/proposals/all _(MANAGER/ADMIN only)_

Returns paginated proposals.
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `page` | int | 1 | Page number (1-indexed) |
| `size` | int | 10 | Page size |
| `sortBy` | String | `created_at` | Allowed: `created_at`, `status`, `transaction_type` |
| `sortDir` | String | `DESC` | `ASC` or `DESC` |

**Response:** `{ status, message, proposals, totalElements, totalPages }`

Each proposal includes `proposedByUser` for the employee who submitted it, plus `reviewedByUser`, `product`, and `supplier` when available. User passwords are omitted.

### GET /api/proposals/{id} _(MANAGER/ADMIN only)_

Returns one proposal with the same nested display data used by the list endpoint.

### POST /api/proposals/{id}/approve _(MANAGER/ADMIN only)_

Approves a pending proposal and executes the associated transaction.

### POST /api/proposals/{id}/reject _(MANAGER/ADMIN only)_

Rejects a pending proposal.

### GET /api/proposals/pending-count _(MANAGER/ADMIN only)_

Returns `{ pendingProposalsCount }`.

## Frontend Integration Guide

All API calls go through `src/lib/axios.js` (axios instance with JWT interceptor). Base URL is `VITE_API_URL` env variable.

### React Query Hooks

Import from the matching feature API file under `frontend/src/features/<feature>/api.js`.

#### Products (`products/api.js`)

```jsx
// List products (paginated or flat based on params)
useProducts({ page, limit, search, categoryId });
// Returns: { products, totalElements, totalPages, ... }

// Single product
useProduct(id);

// Create product (FormData — multipart)
useCreateProduct(); // payload: FormData with: imageFile, name, price, stockQuantity, categoryId, description

// Update product (FormData — multipart)
useUpdateProduct(); // payload: { id, data: FormData }

// Delete product (soft delete)
useDeleteProduct(); // payload: id
```

#### Transactions (`transactions/api.js`)

```jsx
// List transactions (paginated)
useTransactions({ page, limit, search, filter });
// Returns: { transactions, totalElements, totalPages }

// Single transaction
useTransaction(id);

// Transactions by month (for reports)
useTransactionsByMonth(month, year);

// Make a purchase (ADMIN/MANAGER only)
usePurchaseTransaction(); // payload: { productId, supplierId, quantity, description }

// Make a sale (all authenticated users)
useSellTransaction(); // payload: { productId, quantity, description }

// Update transaction status (ADMIN/MANAGER only)
useUpdateTransaction(); // payload: { id, status: "COMPLETED" | "PROCESSING" | "PENDING" | "CANCELLED" }
```

#### Dashboard (`dashboard/api.js`)

```jsx
useDashboardStats(); // returns { dashboardStats }
```

#### Proposals (`proposals/api.js`)

```jsx
useProposals({ page, limit, sortBy, sortDir }); // list proposals
useProposal(id); // single proposal with proposer/product/supplier/reviewer details
usePendingProposalsCount();
useApproveProposal(); // payload: { id, reviewNote? }
useRejectProposal(); // payload: { id, reviewNote? }
```

#### Audit Logs (`auditLogs/api.js`)

```jsx
useAuditLogs({ page, limit }); // list audit logs
useAuditLog(id); // single audit log with actor details
```

#### Categories (`categories/api.js`)

```jsx
useCategories(); // list all
useCategory(id); // single
useCreateCategory(); // payload: { name, description, imageUrl, isActive, displayOrder }
useUpdateCategory(); // payload: { id, ...fields }
useDeleteCategory(); // payload: id
```

#### Suppliers (`suppliers/api.js`)

```jsx
useSuppliers(); // list all
useSupplier(id); // single
useCreateSupplier(); // payload: { name, address, contactInfo, email, website, taxCode, status }
useUpdateSupplier(); // payload: { id, ...fields }
useDeleteSupplier(); // payload: id
```

#### Users (`users/api.js`)

```jsx
useUsers(); // list all (ADMIN only)
useUser(id); // single
useUpdateUser(); // payload: { id, name, email, phoneNumber, role }
useDeleteUser(); // payload: id
```

#### Product Suppliers (`products/api.js`)

```jsx
useProductSuppliers(productId); // suppliers for a product
useSupplierProducts(supplierId); // products from a supplier
useAddProductSupplier(); // payload: { productId, supplierId, unitCost, isPreferred }
useDeleteProductSupplier(); // payload: { productId, supplierId }
```

### Authentication Flow

- **Login:** POST `/api/auth/login` → response includes `token` and `role`
- **Token storage:** Stored in `localStorage` as `token`
- **Auto-attached:** `axios.js` interceptor automatically adds `Authorization: Bearer <token>` to all requests
- **ProtectedRoute:** Redirects to `/login` if no token or session expired
- **AdminRoute:** Additional check that user role is `ADMIN`
